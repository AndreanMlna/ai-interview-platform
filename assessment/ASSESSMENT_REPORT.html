1. Executive Summary & Domain Immersion (5 Pilar)

Platform evaluasi wawancara kerja berbasis kecerdasan buatan (AI Interview Platform) bukan sekadar aplikasi transkripsi percakapan teknis, melainkan sistem dengan tingkat dampak sangat tinggi (high-stakes decision system). Dalam tradisi rekayasa Monozukuri, kami mengevaluasi sistem ini dari prinsip pertama (first principles) dengan membedah 5 Pilar Domain:

5 Pilar Domain Konteks Industri & Realitas Kerja Implikasi Rekayasa Produk
1. The Product Platform wawancara suara real-time dua arah (*Gemini Live WebSocket*) dan asesmen kompetensi otomatis. Latensi audio harus minimal (< 50ms), status transisi terprediksi, dan laporan komprehensif.
2. The Industry Ekosistem rekrutmen Indonesia menghadapi inefisiensi screening manual dan bias subjektif asesor manusia. Penilaian wajib berbasis bukti riil (*evidence quotes*) dan mendukung koreksi manusia (*assessor override*).
3. What It Is For Menghasilkan evaluasi kecocokan kandidat (*fit/gap*) yang objektif, transparan, dan dapat dipertanggungjawabkan. Skala level L1–L5 harus konsisten; skill yang tidak sempat diuji wajib dinyatakan secara gamblang (*unassessed*).
4. The Users Asesor, recruiter, dan hiring manager yang memerlukan ringkasan cepat untuk mengambil keputusan dalam 30 detik. Menyajikan Executive KPI Scorecard dan Interactive Filter Pills agar recruiter tidak overload.
5. The People Affected Who Never Chose It Kandidat pelamar kerja. Mereka tidak memilih sistem ini dan tidak bisa menolak dievaluasi oleh AI. Kesalahan teknis sistem merugikan karier nyata. Zero-tolerance kebocoran data pribadi (UU PDP No. 27/2022), mitigasi halusinasi, dan perlindungan privasi mutlak.

Constraint Signal (Eskalasi ke Technical Lead):
  1. Sinkronisasi Eksekusi LLM: Panggilan FitGap::Engine berjalan sinkron saat HTTP GET/POST dari frontend. Jika inferensi AI mengalami latensi > 15 detik, gateway HTTP memicu timeout 504. Direkomendasikan migrasi ke asynchronous worker Sidekiq.
  2. Dual-Type Representation: Level kompetensi disimpan sebagai integer 1..5 di database Rails, namun kerap diakses sebagai representasi teks ("L3") di antarmuka. Diperlukan parser dwiarah terpusat.

3. Strategi Revamp & Evaluasi Trade-off (Option A vs Option B)

Dimensi Evaluasi Option A: Full Event-Driven Microservices Option B: Pragmatic Hexagonal Resiliency (Dipilih)
Product Impact vs Cost Biaya refactoring masif, overhead infrastruktur tinggi, risiko kegagalan tinggi dalam batasan waktu. Optimal: Memperbaiki batas kontrak (boundary seam), mempertahankan Sidekiq yang ada, biaya terukur.
Maintainability Tinggi beban operasi (distributed tracing, dead letter queues, multi-repo complexity). Sangat Tinggi: Clean architecture modular, mudah dipelihara dan diproteksi dengan RSpec & Vitest.
Failure Modes Message broker bottleneck saat beban spike. Panggilan LLM terlindungi oleh exponential backoff, timeout, dan graceful fallback narrative.
Contextual Fit Over-engineering yang tidak tepat sasaran untuk kebutuhan saat ini. Tepat Sasaran: Menyelesaikan P0–P2 secara tuntas dengan bukti verifikasi empiris.

Matriks 6 Kondisi Interaksi (Interaction States Matrix)

1. Loading State

Skeleton visual terstruktur mempertahankan layout geometris tanpa ada Cumulative Layout Shift (CLS = 0).

2. Empty State

Tampilan bergaris putus-putus ramah pengguna saat tidak ada keterampilan terkonfigurasi atau hasil evaluasi kosong.

3. Error State

Pesan pemulihan informatif dilengkapi tombol aksi Try Again untuk fetch ulang data.

4. Partial State

Peringatan kontekstual untuk skill yang baru dibahas singkat (*Low Confidence: warrants dedicated session*).

5. Long Text State

Pencegahan luapan teks horizontal menggunakan break-words dan whitespace-pre-wrap.

6. Responsive Views

Tabel terbungkus dalam kontainer scroll horizontal dan navigasi fleksibel untuk perangkat smartphone maupun desktop.

7. AI Verification Moment

Saat asisten AI pertama kali membuat pengujian komponen, AI berasumsi bahwa nilai level pada payload adalah string langsung ("Advanced"). Pemeriksaan empiris oleh insinyur mendeteksi bahwa database Rails menggunakan integer (1..5), sehingga kode asli akan me-render nilai cacat (Lundefined).
